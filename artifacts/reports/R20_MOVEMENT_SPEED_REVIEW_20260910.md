# R20 빠른 이동 속도 비교 — 2026-09-10

상태: **2배 이동 속도 기본 채택 완료**. 사용자가 걷기1.40m/s·달리기2.10m/s 설정을 선택했다.2·3·4인 Shared Arena와 기본 Unity 메뉴는 검증한2배 프로필을 그대로 사용한다.

속도 설정과 실측을 구분한다. 접촉 마찰은 물리 계산 뒤 속도를 줄이며, 기존 마찰·질량·중력은 보존했다.4m 환산값은 가속·정지·충돌을 제외한 거리/정속 계산이며 실제 경기 시간 측정이 아니다.

처음에는 발 주기를 덜 늘리고 보폭을 길게 했으나, 짧은 리그의 도달 범위와 표면 변형 기준을 넘었다. 최종 후보는 보폭을 기존과 비슷하게 유지하며 보행 주기를 속도에 맞춘다. 빠른 동작에서 발·골반의 들림/상하 이동은1~2mm 줄여 변형을 줄였다. 사용자는 발놀림도 빨라진2배 영상을 확인하고 이를 선택했다.

## 검증

- 각 속도의 걷기→달리기→점프→공중 반전→착지→정지를60Hz로 검사했다. 정속 구간과 전환의 모든 sample을 포함해 mesh 표면 각, 다리 도달 보정, 바닥 침범, 접지 중 발의 움직임, 판정용/표시용 pose 오차를 확인했다.
- 두 빠른 후보 모두 기존 허용 범위를 통과했다.1.5배/2배 최대 표면 각42.78°/41.73°(<45°), 도달 보정2.03/2.92mm(<3mm), 바닥 침범6.67/7.39mm(<8mm), 측정 안정 지지 구간 접지 유지100%였다. 판정용 pose 오차는10.61mm 이하(<30mm)다.
- 1.5배/2배에서 실제 잡기 유지 중 전진·달리기·점프 후 버튼을 놓아1회만 던지는 검사를 통과했다.60tick 동안 잡기를 유지했고 점프1회·Throw1회, 일반 충돌 피해0이었다. 최대 GripStress는0.453/0.547로 기존 정책을 유지했다.
- 2배 프로필에서15·20·30·60·90·120·144·240FPS 상당의 렌더 일정, 불규칙 간격,200ms 지연, 표시 생략을 비교했다.1,080tick/18초마다 이동·bone·물리 부위·camera 오차0, 펀치10·피격10·Throw1·Down1·회복1로 일치했다. 원본 timestamp 양손 입력과 실제 Unity post-physics loop 검사도 통과했다.
- 후보용 수치/진입 메뉴를 추가했으며, 원본 모델·리그·weight·clip9개 자산은 기존 SHA-256과 같다. 펀치 속도,150ms hold, 점수·Down 시간, 점프 높이와 하중 정책은 변경하지 않았다.

## 영상과 실행

[이전 기본→1.5배→2배 비교 영상](../../.codex_tmp/movement-speed-20260910/Media/Comparison60.mp4)은 각각6초, 전체18초다. 영상의 “현재” 표시는 속도 채택 이전의 기준을 뜻한다. 동일한 고정 카메라에서 같은 타이밍으로1.5초 걷고1.5초 달린다. 바닥은 고정되어 있고 실제 캐릭터 Root가 이동한다.4명은 좌우 두 줄로 움직여 이동 거리와 발놀림을 비교한다.

Native render1,080프레임을60fps로 인코딩했고, 실제 decode1,080프레임·18초·서로 다른1,023프레임을 확인했다. 타임스탬프 간격은1/60초이며 영상 배속이나 중간 프레임 합성은 사용하지 않았다. 원본과 decode의 이미지 방향·자막을 육안으로 확인했다.

## 채택과 후속 통합 확인

사용자가2배 속도를 기본으로 선택했다. 속도만으로 짧은 라운드를 보장하지 않는다. 실제 맵의 접촉까지 걸리는 거리, 회피/추격, 넉다운 뒤 퇴장 경로를 함께 시험해야 한다.

4명이 사방으로 오래 흩어지는 시나리오는 기존 카메라 최대 dolly15m에 더 빨리 닿았다. 좌우 비교 영상은 이 제약을 숨긴 다인 카메라 최종 합격 자료가 아니다. 선택된2배 속도로 실제 경기장 범위·카메라 추적을 함께 검토한다. 현재 무한 바닥 검토 장면의 문제를 해결하려고 속도를 다시 낮추거나 카메라 한계를 임의로 넓히지 않았다.

[구조화 결과와 소스 snapshot](R20_MOVEMENT_SPEED_REVIEW_20260910.json)에 수치·검사·영상 정보가 있다. Player Build·commit·push는 하지 않았다.


기본 연결 후 [PlayMode7/7 검사](../../.codex_tmp/movement-speed-adoption-20260910/Play.xml)를 통과했다. 별도 speed override 없이 실제 기본 factory로11종 렌더 일정의 연산 일치를 재검증했다. [기본 속도의 FPS 측정](../../.codex_tmp/movement-speed-adoption-20260910/FrameIndependence/Replay.json)에서도 모든 측정 오차가0이었다. 기존 보행 영상과 사방 분산 카메라 회귀는 이전 속도를 명시해 원래 비교 범위를 유지했다. 이는2배 속도의 사방 분산 카메라 문제를 해결한 것으로 계산하지 않는다.
