# 평지 발 고정 절충 후보 — 2026-09-06

사용자가 “그래도 돼”로 이동 속도·발놀림을 함께 조정한 비교 후보 제작을 승인했다.
비교 후보 구현 후 사용자가 이 접지 절충안으로 진행하도록 승인했다. **현재 프로토타입 기본 보행으로 채택한다.**
재미·최종 이동 속도·모델/리그의 최종 확정은 플레이 가능한 통합 프로토타입에서 재검토한다.
이동 속도는 명목 기준 약53% 낮아진다. 작은 속도 차이로 표현하지 않는다.

## 후보 설정과 동작

| 항목 | 이전 비교 기준 Walk / Sprint | 채택한 프로토타입 Walk / Sprint |
|---|---|---|
| 설정 속도 | 1.50 / 2.25m/s | 0.70 / 1.05m/s |
| 한 발의 명목 주기 | 1.65 / 2.50Hz | 3.00 / 4.50Hz |
| 실제 정속 이동 | 1.402 / 2.152m/s | 0.602 / 0.952m/s |
| 관측 발 기준점 들림 | 18.7 / 21.0mm | 8.6 / 9.1mm |
| 관측 앞뒤 이동 폭 | 81.4 / 104.1mm | 127.0 / 127.0mm |

발을 더 낮게 들고 자주 딛는 형태다. 기준 속도와 주기에서 보폭을 계산하며,
안정된 평지 지지 중에는 발 목표의 월드 좌표를 유지한다. 방향 전환·가감속·점프·정지 때는
고정을 해제하고 잔여 보정량을 점진적으로 없앤다. Reset은 저장된 고정점과 보정량을 폐기한다.
공중 이동은 기존 Rigidbody 물리이며 Jump/Landing clip은 추가하지 않았다.

골반을 낮추는 양과 보행 강도 필터를 함께 조정했다. 작은 보행 강도에서 자세를 완만하게 시작해
점프 시작·착지 시 무릎이 빠르게 꺾이는 문제를 줄였다. 발목을 추가로 비틀거나 뼈 길이를 늘리지 않았다.

## 검증 결과

- 후보 정속8방향×Walk/Sprint16조건에서 고정 목표 도달 범위 초과0m.
- 비교 캡처의 정속 지지 표본100%에서 고정 활성. 고정된 발 기준점 최대 이동 속도 약0.018mm/s.
- 무릎 최대 굽힘 Walk약66.65° / Sprint약65.39°, 정속60Hz 한 표본 최대 관절 변화 약11.99° / 18.62°.
- 후보 Walk23frame·Sprint15frame의 한 주기 전체 표면에서 인접 면45° 이상 꺾임0,90° 이상 뒤집힘0.
- 표면 최대 인접 면 각도 약42.51° / 41.77°. 발 목표 도달 오차 최대 약3.18e-7m.
- 8방향 점프, 공중 반전/회전/정지, 착지 후 달리기, 재점프, 팔 점유, Reset,30/60/120fps 등18조건 통과.
- 공중에서 양발 고정이 해제되는지, 정지 후 초기 대기 자세로 돌아오는지 검사했다.
- 기존 접촉 전환15°·일반 관절20°/60Hz 기준은 완화하지 않았다. 보행 주기 진행 상한만 후보의 설정 주기에 맞춘다.
- 전체 EditMode85/85·PlayMode21/21 통과, skip0. 이 실행의 점프 전환18조건은 후보 설정을 사용했다. 기존 기본 보행 비교와 캡처 갱신 검사도 포함한다.

실제 player-loop frame 이후 촬영했다. 배경만 움직여도 성공하는 검사에 의존하지 않고,
기존 skinning 갱신/CPU pose 일치 검사도 함께 실행했다.

## 남은 범위

**발 뼈 기준점 고정과 발바닥 표면의 완전 접촉은 다르다.** 후보의 최대 바닥 침범은 Walk약5.9mm,
Sprint약6.8mm였다. 기존8mm 검토 기준 이내지만 잔차가 남는다. 발바닥 전체의 회전 고정,
경사·계단·움직이는 발판과 급격한 방향 전환 중 미끄러짐0은 완료로 표시하지 않는다.
고정은 안정된 지지에 한정하며, 전환 중에는 부드러운 해제를 우선한다.
표면 검사는 인접 면 기준이며 비인접 자기 교차 전수 검사가 아니다.

프로토타입 사용은 승인됐다. 통합 후 조작감 재평가, 지형별 발바닥 보정, 실제 게임 Prefab·전투·Ragdoll·network 통합은 후속이다.
원본 r16/r20, 승인 하체 웨이트와 펀치는 유지했다. Player Build·commit/push는 수행하지 않았다.

## 실행·비교·재검사

Unity 기본 메뉴 `Project Hotfix → Prototypes → Open Physics Jump Review`에서 채택한 접지 설정으로 Play한다.
`Open Foot Plant Candidate`는 같은 설정의 기존 메뉴 진입점으로 유지한다.
WASD 이동, Shift 달리기, Space 점프, R 초기화. 이전 보행 비교는 `Open Previous Gait Comparison`에서 열 수 있다.

영상 폴더: `.codex_tmp/foot-plant-candidate-20260906/Review-20260905-191856/Media/`.

- `Comparison.gif` / `.mp4`: 왼쪽 채택 이전, 오른쪽 이번에 채택한 설정. 영상의 “현재/후보” 자막은 제작 당시 기준이다. 위 Walk, 아래 Sprint.
- `Fixed.gif` / `.mp4`: 후보의 실제 이동을 고정 카메라로 확인.
- `JumpTransitions.gif`: 공중 반전 착지와 착지 후 달리기 전환.

GIF는 실제 속도로 재생하며 마지막 정지와 반복 안내를 별도로 추가했다.
MP4 두 개 모두 디코딩120frame·60fps·2초를 확인했다.
소스 snapshot·원시 측정·검사 XML·영상 SHA256은 [구조화 기록](R20_FOOT_PLANT_CANDIDATE_20260906.json)에 연결한다.

재검사는 `FootPlantCandidate_HoldsWorldPosition`과 `Candidate_WorldAnchorsRemainReachable`을 사용한다.
점프 전환 검사는 이제 별도 환경 변수 없이 채택한 기본 설정을 사용한다.
`PHX_REVIEW_METRICS_ONLY=1`은 영상 없이 CPU 수치만 검사하는 실행이며 캡처 증거로 사용하지 않는다.

## 프로토타입 진행 및 재검토 시점

사용자는 접지 절충안으로 먼저 진행하고 프로토타입이 나온 뒤 다시 판단하기로 했다.
지금은 승인한 모델·리그·하체 웨이트를 유지한다. 모델링/리깅 재작업은 지금 실행하는 요청이 아니다.

첫 통합 프로토타입에서 같은 맵의 두 캐릭터가 이동·추격·회피·점프와 기본 타격/잡기를 시험할 수 있게 되면
사용자와 아래 항목을 함께 확인한다. 기능 구현 중인 현재 시점에 같은 속도 승인을 반복해서 요청하지 않는다.

1. 대표 구간 이동 시간과 추격/회피 반응이 답답한지.
2. 점프 거리·착지 전환과 공격/잡기 거리의 조합이 자연스러운지.
3. 화면에서 발 접지·발놀림이 읽히며 상대 행동을 판단할 수 있는지.
4. 속도·주기·보폭 조정만으로 충분한지, 체형·다리 길이·관절 배치·웨이트 재작업이 필요한지.

재검토 결과와 사용자 결정을 CHR-012/QA-002의 체감 검토 근거로 남긴다.
모델·리그 재작업이 필요하면 구체적인 변경 범위를 제시한 뒤 진행한다.
이는 게임 재미를 검증했거나 최종 캐릭터 Gate를 완료했다는 뜻이 아니다.

채택 후 기본 생성 경로와 메뉴를 변경하고 PlayMode21/21을 다시 통과했다. 기본 접지 설정을 기존 캡처 테스트에서 직접 확인했다.
[프로토타입 채택 기록](R20_FOOT_PLANT_PROTOTYPE_ADOPTION_20260906.json)에 사용자 결정과 새 소스 snapshot·검사 결과를 보존한다.
