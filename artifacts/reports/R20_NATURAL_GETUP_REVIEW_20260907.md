# 무력 래그돌·단계별 회복 수정 후보

사용자는 래그돌이 힘이 풀린 상태여야 한다고 확인했고, 이전 회복 애니메이션이 어색하다며 자연스럽게 서도록 요청했다.
기존 후보의 자세 유지 구동력을 제거하고, 상체·체중 이동·마지막 기립을 분리한 수정 후보를 만들었다.
자연스러움의 최종 판단은 사용자 시각 검토 대상이다.

## 달라진 움직임

- PhysicsTumble 동안 angular pose drive의 spring·damper·maximumForce를 모두0으로 한다. 기본 자세로 돌아오려는 힘이 없다.
- 관절 연결·회전 제한·충돌·중력과 수동 angular damping은 유지한다. 무력 상태가 뼈의 분리나 무제한 관절 회전을 뜻하지는 않는다.
- 회복 단계에 들어왔을 때만 자세 구동력을 켠다. 중단되거나 손/발 위치가 부적합하면 같은 tick에서 무력 상태로 돌린다.
- 아주 짧은 발을 각각의 Rigidbody로 두던 구성은 종아리와 함께 충돌 처리하도록 단순화했다. 기본 무력 후보는10 body이고 합계20kg이다.
- 팔꿈치 축과 좌우 제한 방향을 실제 충격 반응으로 검사한다. 무릎도 굽힘과 뒤로 꺾임을 구분한다.
- 기존 가슴 아래 지점을 향해 몸 전체를 올리던 목표 대신, 골반 아래의 유효한 기립 공간을 확인하고 골반을 중심으로 상체를 세운다.
- 준비0~0.4초, 상체 세우기0.4~1.12초, 체중 이동1.12~1.65초, 마지막 기립1.65~2.15초, 정리2.35초의 순서다. 실제 물리 안정 전에는 조작을 풀지 않는다.
- 두 팔의 시작과 바닥 해제 시점을 조금 다르게 하고, 무릎 굽힘/폄과 골반 높이 변화를 함께 넣었다.
- 골반의 시각 하강량은 임의의 고정값이 아니라 실제 FK 다리 단축량으로 계산한다. 발 보정은 도달 범위와8~18° 보정 한도에 맞춰 부분 적용한다. 모든 구간의 완전한 발 고정을 주장하지 않는다.
- 손이 몸에 지나치게 가까워 팔꿈치가 과하게 접히지 않도록 접지 목표와 최소 도달 거리를 조정했다.

## 클립과 실행

기존 `GetUp_FaceUp.anim` / `GetUp_FaceDown.anim`을 수정했다. 두 클립은 각각2.35초,30fps 기준72키 시점이다.
21개 뼈의84개 quaternion 채널과 시각 Pelvis의 위치3개 채널을 사용한다. gameplay root의 위치/회전 키와 Animation Event는0이다.
옆으로 누운 경우는 기존 정렬 이후 공통 앞/뒤 클립을 사용한다. 별도의 좌/우 GetUp clip은 없다.

검토: Unity `Project Hotfix > Prototypes > Open Ragdoll Recovery Candidate` → Play →1/2/3/4 방향별 낙하, R Reset.
`RelaxedRagdoll=true`가 새 기본 후보다. 이전 physics-only 검사는 false를 지정해 과거 기준을 독립적으로 보존한다.
클립 제작 소스는 `GetUpClipAuthoring.cs`, 표현·접지 보정은 `GetUpAnimationPose.cs`, 권한 동작은 `RagdollRecoveryReview.cs`다.

## 검사 범위

- 앞/뒤/좌/우 낙하, 천장, 천장 제거, Reset, 정지 측면 정렬2조건, 애니메이션 중단 후 재시작.
- Start 초기화, 서 있는 상태의 Down, 회복 후 이동과 반복 Down, 설정 복원과 Reset.
- 별도 공중 fixture에서9개의 동적 관절 모두 자세 구동력0을 확인하고, 좌우 팔꿈치가 외부 impulse에 대해 앞쪽으로 굽히는지 검사한다.
- clip의 실제 몸통·팔·다리 키 변화,87채널,길이,root curve/event0, 표현 적용 전후 authority root 위치·회전·속도 불변.
- 기존 인접 면45°·joint gap15mm·복귀 bone head 이동15mm 기준을 유지한다. active 구간은2step마다 표면을 검사한다.

정지 측면 fixture의 준비 구간은 기존처럼 timer를 미리 소진하고 잠깐 중력을 끈 상태에서 시작하며, 정렬 시작부터 중력을 복원한다.
일반 낙하 조건은 처음부터 중력이 켜져 있다. 이 둘을 동일한 낙하 증거로 합치지 않는다.

## 범위와 후속

원본 `.blend`·mesh·weight·리그를 변경하지 않았다. 기존 펀치·접지·잡기 점프와 던진 뒤 일반 충돌 Damage/피해 누적 제외 규칙을 유지한다.
물리 몸통은 하나의 주 몸체이고 발은 종아리에 결합된 근사 구성이다. 모든 척추/발목의 자유도를 구현한 최종 해부학적 ragdoll은 아니다.
복잡한 지형, skin 전체의 지면 접촉·자기 교차, 잡힌 팔의 회복,2/3/4인 성능·peer·정식 게임 통합은 후속이다.
수치 검사를 통과한 것만으로 동작의 자연스러움이나 최종 조작감을 승인 처리하지 않는다.
Player Build·원본 모델 저장·commit/push는 수행하지 않는다.

## 검증 결과

전체 EditMode110/110·PlayMode36/36 통과, skip0.10조건·2,209표면 표본에서 최대 인접 면각19.51° 미만, 최대 joint gap14.16mm 미만이었다. 손 완전 접지 표본의 목표 오차는0.13mm 미만이다.
발 보정은 조건별 최대 가중치 약0.78~1.0으로 부분 적용됐다. 모든 조건에 완전 고정 표본이 있는 것은 아니므로 foot error0만으로 완전 접지라고 해석하지 않는다.
원본/승인 후보4개 SHA-256 유지, 문서 baseline·workflow7개·diff check 통과. 전체 영상2개는 각각160프레임·20fps·8초, 확대 GIF는 원본5초와 정지/반복1초로 확인했다.
[구조화 기록·영상·소스 snapshot](R20_NATURAL_GETUP_REVIEW_20260907.json)을 참고한다.

후속 사용자 요청으로 [일어난 직후 흔들림](R20_GETUP_HANDOFF_FIX_20260907.md)만 수정했다. 회복 clip은 유지하고 force/torque 예약과 물리 handoff 순서를 바로잡는다.
